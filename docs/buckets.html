03 / FILTER EVERY RETRIEVED ROW

A block match is not a neighbor.

Rows outside the block union cannot be radius-r neighbors, by the pigeonhole argument. Rows inside still need full-code validation. Excluded row indices are removed before that check. A scan has no block-union candidate claim.

The boundary stays visible.
With r<bits, use r+1 nonempty blocks. More than r mismatches would be necessary to spoil every block. Matching at least one block is necessary, not sufficient; full Hamming verification removes false candidates.
At radius=bits every row passes, so no bucket index is built. Above the declared block cap, the backend uses a scan without building postings. Dense/duplicate tables can produce more posting visits than the scan's row count. The512-row sparse and dense controls demonstrate both outcomes, not measured performance on learned embeddings.
The actual cosine query wrapper uses the unchanged hyperplanes and stable cosine/id ordering. Exact equality with the previous signature scan is not equality with exhaustive cosine nearest neighbors. No latency, production scale, semantic relevance or new-algorithm claim.
Established multi-index hashing and its pigeonhole principle are credited to Norouzi, Punjani and Fleet. This implements its exact-block special case, not their full optimized search or experimental results.
